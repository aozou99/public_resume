##### 社内 HTML 共有ツール「HTMLShare」の企画・開発・運用

ディレクターやデザイナーなど非エンジニアも AI で HTML を生成するようになった一方、認証付きで安全に共有する手段がなく、Markdown ベースの共有では表現力にも制約があった。この課題に着目して自ら企画を提案し、企画・開発・運用を一人で担当した。提案当日に承認、同日中に MVP 完成、提案から 3 営業日で本番デプロイ（Claude Code 等の AI コーディング支援を活用）。

- React + Vite / Hono on Lambda / Auth0 + Google OAuth / S3 + CloudFront OAC / DynamoDB によるサーバーレス構成の設計
- OAuth broker + 動的クライアント登録(DCR)を自前で設計し、URL を貼るだけで MCP 接続でき、かつ共有者を特定可能に（マネーフォワードでの認可基盤開発の経験を応用）
- WebUI に加え MCP/CLI/SDK を提供し、AI エージェント・バッチ・CI/CD など様々な経路から連携可能に
- User-Agent 判定ではなく署名検証付き App Unfurling を採用し、認証コンテンツを守りながら Slack プレビューに対応
- 成果: リリース（2026 年 6 月末）から約 3 週間で社内約 10 名が利用し、月間共有数十件。ディレクターによる GA + BigQuery の HTML レポートの週次/月次共有や、デザイナーによる Figma 起点の HTML 共有、脆弱性検出 Bot の定期レポートなどに定着
- [開発の経緯・技術詳細をテックブログで公開](https://kodansha.tech/ja/blogs/html-share)

##### RAG を活用した AI 検索機能の開発

編集部からの要望を受け、PoC の作成から本番リリースまで開発全般を単独で主導。従来のカテゴリ・タグベース検索では対応しきれない複合的な検索ニーズ（業種 × ターゲット層 × 企画内容）に応えるため、AWS Bedrock Knowledge Base と RAG を活用した自然言語検索機能を設計・実装した。PoC から本番リリースまで約 10 ヶ月（純粋な開発実装は約 2 ヶ月）で、編集長のフィードバック反映や社内 AI ワーキンググループの利用許諾プロセスなど、大組織で AI 機能をリリースするための合意形成・ガバナンス対応も完走した。

- Bedrock Knowledge Base を核とした RAG 構成の設計（Claude Sonnet 4.6 / Cohere Rerank v3.5 / Amazon S3 Vectors / ECS Scheduled Task による日次データ同期）
- Query Decomposition や Rerank モデルの活用による検索精度の向上
- ビジネス要件を考慮したプロンプト設計（回答の正確性・安全性の担保）
- ルールベース評価と LLM ベース評価を組み合わせた回答品質の評価フレームワークを構築し、品質スコアを 70~80% から 80~90% に改善
- システムプロンプトを Markdown 見出しから XML タグ構造に変更し「1 文 = 1 事実」ルールを明示することで、引用粒度の問題を解決
- WordPress 管理画面から編集部が編集できるパートと、コード側で自動付与する不変ルールを分離し、非エンジニアが運用できるプロンプト管理を実現
- SSE によるストリーミングレスポンス（バッファリングによる滑らかなタイピング表現）や引用表示など、UX を重視したフロントエンド実装
- [開発の知見をテックブログで公開](https://kodansha.tech/ja/blogs/rag-powered-manga-ip-search)

##### 非エンジニアが Claude Code で自走できる開発環境づくり

「ディレクターやデザイナーも AI コーディング支援を使って自分たちで修正できるべき」と考え、ローカル環境構築の自動化を率先して実施（合計約 3 日で整備）。構築の所要時間を 3 時間から 30 分に短縮し、人の実作業はスクリプトを 3~4 回実行するだけの状態にした。

- シークレット設定の自動化: 1Password から手動で env に転記していた作業を、1Password CLI を使ってスクリプト化
- 本番データ同期の脱属人化: 手動の mysqldump と環境ごとの加工に依存していた作業を、マイグレーションツールとして整備
- ローカル再現性の向上: CloudFront のルーティングで実現していた静的ページ表示を、Vite プラグインを自作してローカルでも再現

##### 品質向上のための取り組み

バグが本番デプロイ後に見つかることが立て続けに発生したため、品質改善のために各バグの性質を解析して対策を発案・主導。
対策の一部を下記に紹介。

- 課題
  - 画面の動作確認不足でデグレーションに気づけなかった
- 原因
  - 回帰テストが手動で行われており、確認漏れが発生しやすい
    - 環境変数に依存する観点が確認漏れが発生しており、単体テストでカバーしずらい
- 対策
  - 手動で行っている回帰テストを自動化するために E2E の導入
    - フレームワーク選定からテストケースを追加しやすいための土台づくり（[Zenn で一部 How to を公開](https://zenn.dev/aozou/articles/bd181d4c8bdfe0)）

##### API リファレンスサイト構築で利用した OSS へのコントリビュート

社内プロダクトが利用する API リファレンスサイトの構築で利用した OSS にバグがあり、OSS の中身を解析して修正を行った。

- [Release v4.2.0 · PaloAltoNetworks/docusaurus-openapi-docs](https://github.com/PaloAltoNetworks/docusaurus-openapi-docs/releases/tag/v4.2.0)
  - 会社で利用している Github アカウント(@aoki-atsushi)で 2 つの PR を出し採用されパブリッシュされた

##### 成果

- 約 200 の連携サービスが利用する基盤の開発・運用を安定して推進
- 環境変数依存の観点を含む回帰テストを自動化し、デグレーションを本番前に検知できる体制を整備
